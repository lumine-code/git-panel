# Diff performance and ownership

Diff text, hunk boundaries, and line-level highlighting remain complete when detailed word highlighting is omitted. Each paired deleted and added line has an 8 ms comparison budget and a maximum edit distance of 256 tokens. Lines longer than 256 Ki UTF-16 code units skip detailed comparison; this is a string-length limit, not a byte limit, and a supplementary Unicode character occupies two code units. One population pass also has a 50 ms monotonic elapsed-time budget checked between pairs. Parsing, native buffer construction, marker notifications, and rendering have their own costs, so these budgets do not promise that the entire diff opens within 50 ms.

When a limit is reached, the viewer shows one notice explaining that some changes are highlighted by line. The complete raw patch and staging coordinates are preserved. `MultiFilePatch.getWordDiffStats()` reports the paired lines, computed detail, omitted detail, unchanged pairs, elapsed computation time, and omission reasons. Collapsing and expanding a file updates the summary for currently visible hunks.

Each built `MultiFilePatch` owns its native backing buffer. Its creator calls `dispose()` when the snapshot is replaced, rejected as stale, or closed. A consumer that shares the model acquires a lease with `retain()` and disposes that lease when finished. Model disposal releases its own retain rather than destroying a buffer that a mounted editor still owns. Standalone preview `PatchBuffer` slices have their own idempotent `dispose()` method.

Repository caches own their resolved patch and commit snapshots and release them on eviction, clearing, or destruction. An owned snapshot read invalidated while still in flight disposes its eventual model and rejects with `ABORT_ERR`; an invalidated ordinary metadata read completes for its waiting caller without restoring its cache entry. History-only commit metadata creates no native patch buffer until its diff is requested. Pane consumers clone cached snapshots before mutation, preserving independent collapse state, text, marker coordinates, and viewport buffers across simultaneous views.

Native marker replacement is batched so subscribers observe a completed layer once rather than processing every inserted marker. Large-diff checks should cover cold and warm cache reads, many small files, large expanded files, long individual lines, repeated refreshes, and repeated preview slices. Measure Git or API time, parsing, construction, word detail, adoption, publication, useful paint, and remaining native buffers separately.
